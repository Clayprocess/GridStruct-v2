## 3. 第一部分：Qoder 脚本验收

终端输出原文（正式采集）：

```
qoder cn.exe 点数 160，首次 41.6ms，命中中位 2.3ms（最大 41.6），含补父链中位 2.3ms，超过 300ms 的命中 0 次，一次性大批量 0 次，平均层数 11.6
  最内层大小：最小 (84, 30)，中位 (2305, 1344)
```

诊断脚本输出原文（正式采集）：

```
qoder cn.exe [Chrome_WidgetWin_1] 点数 160
  MSAA：命中中位 2.9ms，补父链中位 39.5ms，平均层数 2+9，最小元素面积中位 3563520.0
  UIA ：命中中位 2.3ms，含父链中位 15.6ms，平均层数 18.6，最小元素面积中位 3097920.0
  UIA 最内层控件类型：{'Button': 13, 'Group': 145, 'Text': 2}
```

与期望对比：**当次测量符合，但复现不稳定**。

- 当次：最内层最小 84×30，局部元素（面积 <200k px²）37/160；诊断脚本同口径 34/160，比例接近；最大命中 41.6ms，无超过 300ms。中位 2305×1344 是因为设置页大面积是空白/大容器。
- 复现：随后在相同页面、相同坐标重跑，`probe_snap_hit` 回到 1.0 层、最内层全部 `2560×1392`；重复查询 3 次、间隔 1.2s 仍为整窗。Chromium 的无障碍子树对“逐层 FindAll”时隐时现。

### 4.2 左右两组各一点的逐层诊断

左组（140,1416）输出原文：

```
explorer.exe 命中路径：[(55, 1392, 220, 48)]
  第 0 层：子元素 3 个，空矩形 0 个，含该点 [(0, 1392, 2560, 48), (55, 1392, 220, 48)]
  第 1 层：子元素 0 个，空矩形 0 个，含该点 []
```

托盘（2400,1416）输出原文：

```
explorer.exe 命中路径：[(2271, 1392, 289, 48)]
  第 0 层：子元素 3 个，空矩形 0 个，含该点 [(0, 1392, 2560, 48), (2271, 1392, 289, 48)]
  第 1 层：子元素 0 个，空矩形 0 个，含该点 []
```

### 4.3 三个问题的回答

1. **这两个点上，UIA 的最内层是单个图标还是整组？** 单个图标。同一坐标用 `ElementFromPoint`：
   - 左组（138,1416）：`Button`（`Taskbar.TaskListButtonAutomationPeer`），`44×48`
   - 托盘（2400,1416）：`Button`（`SystemTray.AccentButton`），`24×48`
2. **整组那一层，“子元素”和“空矩形”各是多少？** 子元素 **0 个**，空矩形 **0 个**（不是空矩形占位，是根本没有枚举出子元素）。
3. **结论**：Windows 本身能给出组内单个图标，是 GridStruct 的逐层 `FindAll` 在组这一层漏掉了子元素，停在 220×48 / 289×48，不是外壳只给整组。
