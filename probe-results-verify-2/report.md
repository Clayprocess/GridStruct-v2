# 元素吸附验收报告（PR #61 第二轮）

验收日期：2026-11-10
被测代码：分支 `claude/project-thread-83w7rl`，提交 `b17eb2d`（任务栏 UIA、Electron 按浏览器双查、截图开始时预取 UIA 程序子元素）。
脚本：`tools/probe_snap_hit.py`、`tools/probe_snap_apps.py`（均为仓库内现有脚本）。

## 1. 环境

- Windows 11 企业版 10.0.26100
- 显示器 2 台：主屏 2560×1440 @100%（探测窗口在主屏最大化）；副屏 1536×960 @125%
- Qoder CN 0.5.7（Electron，窗口类 `Chrome_WidgetWin_1`）

## 2. 方法与偏差

- 任务栏：主屏任务栏有固定/打开的应用图标，`--class Shell_TrayWnd --grid 60x1`；另用 120 点密集扫描复核分组情况。
- Qoder：进程名 `qoder cn.exe`，窗口类 `Chrome_WidgetWin_1`。
  该版本 Qoder 没有“打开文件夹”入口：文件菜单只有“设置…/关闭窗口”，用 `-n`、`--new-window` 启动参数打开空文件夹时都复用同一窗口。因此用“新建窗口”的空任务页（未打开任何代码文件）最大化探测；原聊天窗口被完全覆盖，未产生采样点。
- 隐私：未打开真实文档/邮件/聊天；脚本不记录名称和文字。

## 3. 第一部分：脚本验收

### 3.1 任务栏

终端输出原文：

```
explorer.exe 点数 60，首次 67.3ms，命中中位 0.0ms（最大 67.3），含补父链中位 0.0ms，超过 300ms 的命中 0 次，一次性大批量 0 次，平均层数 1.9
  最内层大小：最小 (44, 48)，中位 (2560, 48)
```

与期望对比：**部分符合**。

- 应用按钮能吸到单个图标：`44×48`；开始按钮 `55×48`。
- 60 个等距点覆盖整条任务栏，只有 6 个点落在图标上，其余落在空区（最内层为整条 `2560×48`），所以中位数是整条任务栏。
- 120 点密集扫描看到四种最小层级（本机任务栏布局）：
  - `44×48` / `55×48`：应用按钮、开始按钮（单图标）
  - `220×48`：左侧“开始/搜索/任务视图/小组件”一组
  - `289×48`：右侧托盘图标一组
  - `2560×48`：空白区域
- 即左侧按钮组和托盘组在 UIA 树里本身就是“一组图标”的元素，最小层级只能到整组，无法再拆到单个图标；这是 Windows 外壳暴露的粒度，不是吸附实现丢层。

### 3.2 Qoder

终端输出原文：

```
qoder cn.exe 点数 160，首次 13.2ms，命中中位 1.9ms（最大 13.2），含补父链中位 1.9ms，超过 300ms 的命中 0 次，一次性大批量 0 次，平均层数 1.0
  最内层大小：最小 (2560, 1392)，中位 (2560, 1392)
qoder cn.exe：没有可测的点
```

与期望对比：**不符合**。

- 160 个点的最内层全部是整块内容区 `2560×1392`，平均层数 1.0，吸不进侧栏、标签页、按钮；没有超过 300ms 的命中（最大 13.2ms）。

诊断脚本（`probe_snap_apps.py`）输出原文：

```
qoder cn.exe [Chrome_WidgetWin_1] 点数 160
  MSAA：命中中位 3.0ms，补父链中位 41.8ms，平均层数 2+9，最小元素面积中位 3563520.0
  UIA ：命中中位 2.5ms，含父链中位 15.9ms，平均层数 19.0，最小元素面积中位 3097920.0
  UIA 最内层控件类型：{'Button': 7, 'Group': 148, 'Text': 2, 'Hyperlink': 2, 'Image': 1}
qoder cn.exe [Chrome_WidgetWin_1]：没有可测的点（窗口被挡住？）
```

定位结论：

- MSAA 树只有 window/client 两级，取不到局部元素，所以“Electron 按浏览器双查”拿不到更小矩形。
- UIA 树有 19 层，7 个点能到 `Button`、2 个 `Text`、2 个 `Hyperlink`，说明 Qoder 的可访问信息在 UIA 侧；但 148/160 个点的 UIA 最内层仍是整块 `Group`，即使改用 UIA，也需要先确认能稳定取到局部元素。
