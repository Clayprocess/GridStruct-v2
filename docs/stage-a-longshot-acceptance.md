# 阶段 A：长截图改进与验收

日期：2026-10-11。范围依据：[总 spec](specs/core-workflow-improvements.md) LS-01 至 LS-12。仅实施阶段 A，未改 OCR、贴图数据或配置格式。

## 改动

本文 `.scratch/` 下的原始导出、日志、基线和截图仅在验收机器本地保留，不随 Git 提交。仓库提交复跑脚本与测量摘要；旧版基线可从提交 `761127d072ab4ad5769f04815e268635a0eee63a` 的 `capture/longshot.py` 重建。

- `ScreenManager.capture_region()` 只抓取选区相交的屏幕区域，保留原物理像素、DPR 和跨屏语义。
- 匹配改为行指纹筛候选，再逐像素确认完整重叠；有多个成立位置或定位信息不足时拒绝。支持有唯一证据的 48px 重叠，不再用白底平均误差接受相似行。
- 失配进入非弹窗恢复状态并停止自动注入滚轮，继续观察选区。滚轮回滚或拖动滚动条都能重新定位；唯一定位只移动视口，不裁掉已确认图像。经过历史区域不重复追加，超过末端才增加内容。
- 自动恢复仍受鼠标选区和目标窗口约束；手动暂停、继续、完成、取消保持可用。预览绿框显示真实恢复位置。
- 在采样前复核前台目标，防止滚轮后切窗的竞态；瞬态内容回到已确认视口时，不误报重叠丢失。

没有新增依赖。NumPy 原先已用于长截图，本次在匹配模块导入时加载；这会将原来的首次匹配加载成本提前到模块加载，不能把热态加速解释为整个程序启动加速。

使用[可见合成窗口脚本](../tools/check_longshot_windows.py)，通过正式 `start_region`、真实 `WheelHook`、屏幕区域采集和 Windows 滚轮输入运行。每次注入前确认目标为脚本自身窗口，并在退出时清理钩子、窗口、定时器及还原光标；不保存用户桌面。

当前设备为单屏 3840×2160、逻辑 2560×1440、DPR 1.5，选区 1200×900 物理像素。已通过纵横快滚、回滚恢复保尾、再次追加、普通反向裁尾、恢复中完成/取消、自动平滑滚动及39px短尾，以及自动重新定位后恢复注入。还验证了控制条保持前台时的后台滚轮（本机路由设为2）和滚轮后、采样前切窗的暂停守卫。最终运行记录见[原始输出](../.scratch/longshot-stage-a/windows-results.txt)。

最终 7 组场景全部通过。纵向恢复专门采用不产生滚轮事件的页面位移，验证持续采样能够自动重新定位；横向仍走真实滚轮回滚。

## 限制与未覆盖范围

- 真实混合 DPI 双屏、负坐标显示器布局尚未验证；这些场景当前只有离屏像素/坐标覆盖。当前设备的性能不能外推其他 CPU 或显示器组合。
- 重叠必须含可唯一辨认且像素稳定的内容。持续动画、视频、闪烁光标、固定头部覆盖滚动区域、分数像素重绘变化可能使匹配拒绝并要求回滚；本阶段没有动态区域屏蔽或亚像素对齐。
- 没有公共内容时不能还原漏采区域；窄重叠若只有空白或重复行也不承诺成功。48px 是通过的合成样本，不是所有页面的保证下限。
- 真实快速确认样本数量有限，仅描述本次观测，不作为长期端到端 P95 门槛。尚无第三方业务页面兼容性覆盖率结论。
- 长图仍在 GUI 线程完成捕获、匹配、整图复制和预览；当前时延已有测量，但更高分辨率或持续动态页面可能需要后续独立优化。
